# Codex-Switch 产品需求文档（PRD）

## 1. 项目信息

| 字段 | 值 |
|------|-----|
| **Project Name** | `codex-switch` |
| **Language** | 中文 |
| **Programming Language** | Electron + React + MUI + Tailwind CSS |
| **版本** | v1.0.0 |
| **原始需求** | 整合 CCX Desktop（API 网关代理）与 CC Switch（配置管理）两大特性，打造一体化桌面应用，让用户无需两个软件配合即可完成多模型 API 代理与客户端配置切换 |

---

## 2. 产品定义

### 2.1 Product Goals

| # | 目标 | 说明 |
|---|------|------|
| G1 | **零门槛连通国内外大模型** | 用户无需手动编辑配置文件，通过图形界面即可将 Codex 等客户端对接 OpenAI、Claude、DeepSeek、通义千问、智谱等模型服务 |
| G2 | **一体化代理与配置管理** | 将 API 网关代理（协议转换 / 请求转发）与客户端配置管理（一键切换 / 自动备份）合二为一，消除双软件协作的安装与操作成本 |
| G3 | **本地化安全可控** | 所有 API 密钥本地加密存储、请求经本地代理转发、零云端依赖，保障数据隐私与服务可用性 |

### 2.2 User Stories

| # | 故事 |
|---|------|
| US1 | 作为 **AI 开发者**，我想要 **一键将 Codex 的 API 地址切换到本地代理**，这样我就能使用 DeepSeek 等免费模型而无需手动编辑 config.toml |
| US2 | 作为 **多模型用户**，我想要 **在同一个界面管理多个模型渠道的 Base URL 和 API Key**，这样我就能根据任务需要快速在不同模型间切换 |
| US3 | 作为 **隐私敏感用户**，我想要 **所有请求和数据都保留在本地**，这样我就能确保代码和对话内容不会外泄至第三方 |
| US4 | 作为 **多工具用户**，我想要 **同时支持 Codex、WorkBuddy、Qorder 等多个 Agent 客户端的配置管理**，这样我就能用一套工具服务所有 AI 编程场景 |
| US5 | 作为 **运维人员**，我想要 **查看请求日志和代理服务状态**，这样我就能快速排查连接失败或模型响应异常等问题 |

## 3. 技术规范

### 3.1 Requirements Pool

#### P0 — Must Have（MVP 必备）

| ID | 需求 | 说明 |
|----|------|------|
| P0-01 | 本地 API 代理服务 | 应用内嵌代理服务器，监听 `localhost:PORT`，接收 OpenAI 兼容格式请求，转换并转发至目标模型 API |
| P0-02 | 多模型渠道管理 | 支持添加/编辑/删除模型渠道，每个渠道配置：Channel Name、Service Type、Base URL、API Key |
| P0-03 | 客户端配置一键切换 | 支持修改 Codex 的 `config.toml` / `auth.json`，将 API 地址指向本地代理或直连远程 API |
| P0-04 | 预置模型模板 | 内置 OpenAI、Claude、DeepSeek、Gemini、通义千问、智谱等常用模型的 Base URL 和协议适配规则 |
| P0-05 | 协议转换引擎 | 将 OpenAI `/chat/completions` 格式请求自动转换为目标模型的原生格式（如 DeepSeek、Claude 等），并逆向转换响应 |
| P0-06 | API Key 本地加密存储 | 使用系统级加密（如 Electron safeStorage）保存 API Key，不以明文落盘 |
| P0-07 | 配置自动备份与回滚 | 每次修改客户端配置前自动备份，支持版本列表查看和一键回滚 |
| P0-08 | 系统托盘常驻 | 最小化到系统托盘，代理服务在后台持续运行，支持托盘菜单快速操作 |

#### P1 — Should Have（重要但非 MVP 阻塞）

| ID | 需求 | 说明 |
|----|------|------|
| P1-01 | 请求日志查看 | 记录代理转发的请求/响应摘要，支持按渠道、时间筛选，方便排查问题 |
| P1-02 | 多 Agent 客户端支持 | 除 Codex 外，支持 WorkBuddy、Qorder、OpenClaw 等客户端的配置文件路径识别与修改 |
| P1-03 | 代理服务状态监控 | 实时展示代理服务运行状态（运行中/已停止）、监听端口、当前活跃连接数 |
| P1-04 | 开机自启动 | 支持设置系统开机时自动启动应用并开启代理服务 |
| P1-05 | 渠道连通性测试 | 提供一键测试按钮，验证渠道的 Base URL + API Key 是否可用，返回延迟与模型信息 |
| P1-06 | 多语言支持 | 默认中文，支持切换英文界面（i18n） |

#### P2 — Nice to Have（未来迭代）

| ID | 需求 | 说明 |
|----|------|------|
| P2-01 | 请求/响应详情查看 | 展示完整的请求头、请求体和响应内容，支持 JSON 格式化和搜索 |
| P2-02 | 流量统计与用量看板 | 按渠道统计 Token 消耗、请求次数、成功率等指标，可视化展示 |
| P2-03 | 自定义请求路由规则 | 支持基于模型名称、请求路径等条件的路由分发规则（如 `gpt-4` → OpenAI，`deepseek-chat` → DeepSeek） |
| P2-04 | 插件/扩展机制 | 允许社区贡献新模型适配器或客户端配置模板 |
| P2-05 | 多配置 Profile | 支持创建多套配置方案（如"工作"/"个人"），一键切换整体配置 |

### 3.2 UI Design Draft

应用采用**左侧导航 + 右侧内容区**的经典桌面布局，整体风格简洁专业。

```
┌─────────────────────────────────────────────────────┐
│  Codex-Switch                              — □ ✕   │
├──────────┬──────────────────────────────────────────┤
│          │                                          │
│  🏠 仪表盘 │  [代理服务状态] ● 运行中  端口: 8080      │
│          │  ┌────────────┐ ┌────────────┐           │
│  🔀 渠道  │  │ 活跃渠道: 3  │ │ 今日请求: 42 │          │
│  管理    │  └────────────┘ └────────────┘           │
│          │                                          │
│  ⚙ 客户端 │  最近请求日志...                          │
│  配置    │                                          │
│          │──────────────────────────────────────────│
│  📋 日志  │                                          │
│          │                                          │
│  🔧 设置  │                                          │
│          │                                          │
├──────────┴──────────────────────────────────────────┤
│  ● 代理运行中 │ localhost:8080 │ 当前渠道: DeepSeek    │
└─────────────────────────────────────────────────────┘
```

**核心页面说明：**

| 页面 | 功能描述 |
|------|----------|
| **仪表盘** | 一览代理服务状态、活跃渠道数、请求统计，提供快速操作入口（启动/停止代理、切换渠道） |
| **渠道管理** | 模型渠道列表（卡片式），支持添加/编辑/删除渠道，每个渠道显示名称、类型、Base URL、连通状态；点击"测试"按钮验证可用性 |
| **客户端配置** | 列出已检测到的 AI 客户端（Codex、WorkBuddy 等），显示当前配置的 API 地址和模型；提供下拉选择目标渠道，一键切换；展示配置备份历史，支持回滚 |
| **请求日志** | 请求列表（时间、渠道、模型、状态码、耗时），点击展开查看摘要；支持按渠道和时间筛选 |
| **设置** | 代理端口配置、开机自启动开关、语言切换、数据存储路径、API Key 加密管理、关于页面 |

### 3.3 Open Questions

| # | 问题 | 影响 | 建议澄清方式 |
|---|------|------|-------------|
| Q1 | 是否需要支持流式响应（SSE/Streaming）的协议转换？ | 影响代理引擎的架构设计（需考虑流式转发 vs 缓冲转发） | 与用户确认 Codex 等客户端是否依赖 streaming 模式 |
| Q2 | 各 AI 客户端（WorkBuddy、Qorder、OpenClaw）的配置文件路径和格式是什么？ | 影响客户端配置模块的适配范围 | 需要用户提供各客户端的配置文件样例 |
| Q3 | 是否需要支持通过 OpenAI 兼容接口访问非 OpenAI 格式的模型（如通义千问的原生 API）？ | 影响协议转换引擎的复杂度和模板数量 | 确认目标模型列表及其 API 格式差异 |
| Q4 | 应用是否需要自动检测已安装的 AI 客户端？ | 影响客户端发现机制的设计 | 确认是否需要扫描文件系统/注册表，还是用户手动添加 |
| Q5 | 代理服务端口冲突时如何处理？ | 影响用户体验和错误提示设计 | 确认是否支持自动选择可用端口，或仅提示用户手动修改 |
| Q6 | 是否需要支持 Windows 之外的操作系统（macOS/Linux）？ | 影响 Electron 打包和系统适配范围 | 虽然用户提到"桌面应用"，但需确认跨平台需求 |

## 附录：核心术语

| 术语 | 说明 |
|------|------|
| **渠道（Channel）** | 一个后端模型服务的连接配置，包含名称、类型、Base URL、API Key |
| **代理服务（Proxy）** | 应用内嵌的本地 HTTP 代理，监听 localhost 端口，负责协议转换与请求转发 |
| **协议转换** | 将 OpenAI 兼容格式的请求/响应转换为目标模型的原生格式 |
| **客户端** | 使用 OpenAI 兼容 API 的 AI 编程工具，如 Codex、WorkBuddy 等 |
| **配置备份** | 修改客户端配置文件前自动创建的快照，用于版本回滚 |
