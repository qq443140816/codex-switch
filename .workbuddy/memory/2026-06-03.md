### BugFix #2 — ELECTRON_RUN_AS_NODE 空字符串问题
- **现象**：`node scripts/start.js` 报 `TypeError: Cannot read properties of undefined (reading 'whenReady')`
- **根因**：`makeCleanEnv()` 先 `delete` 再赋 `env.ELECTRON_RUN_AS_NODE = ''`，空字符串仍被 Electron 检测为该变量存在，导致以 Node.js 模式启动
- **修复**：`scripts/start.js` + `scripts/dev.js` 都改为仅 `delete`，不再设空字符串
- **验证**：构建+启动成功，输出 "IPC 处理器注册完成" + "检测到 2 个已安装客户端"

### BugFix #3 — 白屏（仅菜单栏，无内容）
- **现象**：Electron 启动后窗口白屏，只显示菜单栏
- **根因**：`App.tsx` 使用 `BrowserRouter`，Electron 生产模式用 `loadFile` 加载 `file://` 协议，HTML5 History API 在 `file://` 下无法工作，路由匹配失败导致白屏
- **修复**：`BrowserRouter` → `HashRouter`（`react-router-dom`），HashRouter 基于 URL hash 不依赖 History API
- **额外**：主进程添加 F12 快捷键 toggle DevTools，方便排查渲染器问题

### BugFix #4 — 启动代理按钮点击无反应
- **现象**：界面正常显示，但仪表盘"启动代理"按钮点击无反应
- **根因**：`components/dashboard/ProxyStatus.tsx` 中组件名 `ProxyStatus` 与导入的枚举 `ProxyStatus` 同名冲突，组件声明覆盖了枚举 → `ProxyStatus.RUNNING` / `ProxyStatus.ERROR` 为 `undefined` → `isRunning` 永远 `false` → 启动后状态不切换
- **修复**：枚举 import 改为 `ProxyStatus as ProxyStatusEnum`，组件重命名为 `ProxyStatusCard`，同步更新 `Dashboard.tsx` 引用

### BugFix #5 — 502 没有活跃渠道
- **现象**：WorkBuddy 通过代理请求 API，返回 502 "没有活跃渠道，请先在渠道管理中激活一个渠道"
- **根因**：`client:switch-channel` IPC handler 只写了客户端配置文件，没有调用 `channelStore.setActiveChannel()` 标记渠道为活跃。`RequestRouter.route()` 查找 `ch.isActive === true`，但从未有人设置这个标记
- **修复**：
  - `client-handlers.ts`：切换渠道后调用 `channelStore.setActiveChannel()`
  - `proxy-handlers.ts`：`proxy:set-channel` 也调用 `channelStore.setActiveChannel()`
  - `proxy/server.ts`：`setActiveChannel()` 方法内部同步调用 `channelStore.setActiveChannel()`
